# CHORD LINES（仮題）— コード進行を、トリックにする

駒（コード）を盤に並べて、コード進行を作る。つながりのうち「特徴的なもの」を、スケートボードの技（トリック）のように判定して、得点・コンボ・演出にするゲームの**試作**です。
ブラウザで動く 3D のゲーム（three.js + Web Audio）。**実機の盤（ESP32 + RC522 の8台）がなくても、画面の盤で遊べます。** 実機がつながっていれば、実機の駒で遊べます。

## 動かし方

```sh
cd "/Users/woodbell/Documents/GitHub/Chord-Progression-Game"
sh tools/game.sh              # サーバーを起動して、Chrome で開く（http://127.0.0.1:8800/）
sh tools/game.sh kiosk        # 全画面（展示用）
sh tools/game.sh 8801         # ポートを変える
```

- ES モジュールを使っているので、`index.html` をダブルクリックして開く（`file://`）と**動きません**（「`sh tools/game.sh` を実行してください」という案内が出ます）。必ずサーバー経由で。
- 最初の画面（SPLASH）をクリック（または Enter）すると、音の読み込みが始まって、タイトルに進みます（ブラウザは、クリックの前に音を出せないため）。
- 動作確認は **Chrome のみ**です（Safari・Firefox では確認していません。スマホ表示も、Chrome での再現のみ）。ネットにつながなくても動きます。
- 止めるときは、ターミナルで Ctrl+C。

### スマホ（iPhone など）で遊ぶ（2026-11-23 追加）
スマホの Safari・Chrome でも、遊べるようにした（縦持ち・横持ちの配置・指の操作・軽い描画）。**本物の iPhone では、まだ動かしていません**（Chrome のスマホ表示 = 画面の幅・タッチ・ユーザーエージェントの再現で確認）。スマホに、ゲームのファイルを渡す道は、次のどれか。
1. **同じ Wi-Fi で**: Mac で `sh tools/game.sh lan`（または `python3 tools/game_server.py --lan`）を動かすと、スマホ用の URL（`http://192.168.x.x:8800/`）が出る。スマホで、その URL を開く。**ゲームのファイル（読み取り専用）だけ**を配る。実機の盤・ブリッジへの中継（`/api/`）は、Mac 自身のブラウザにだけ使えて、スマホからは使えない（なので、スマホでは、画面の盤で遊ぶ）。Mac のファイアウォールが受信を止めていたら、許可する。使い終わったら Ctrl+C。
2. **インターネットに置く**（GitHub Pages など。静的なファイルをそのまま置けばよい）: ホーム画面に追加すると、全画面のアプリのように遊べる（`manifest.webmanifest`・アイコンを用意してある）。**公開は、ユーザーが決めること**なので、こちらでは、していません。
- 遊び方（スマホ）: 駒を**タップ → 盤の場所をタップ**で置く / 駒を**2回タップ**で、盤の次の場所へ / 駒を**上へなぞって**持ち上げて置く（**横になぞると、駒の置き場が動く**）/ 駒を**長押し**で、メニュー（編集・削除）/ 盤の駒を**ドラッグ**で動かす / 技の名前の枠を**タップ**で、詳しい説明 / 上のバーは、**横になぞって**ボタンが出る / 「技 ▾」で技の一覧・理由・図鑑、「ガイド」でチュートリアルの説明（始まりに、自動で開く。「いま置くところ」は、上の細い帯に出る）。
- iPhone の**消音スイッチ**がオンでも、音が鳴るように、音の使い方を「再生」にしてある（`navigator.audioSession`・無音の `<audio>`）。**効くかどうかは、実機で未確認**。画面を消す・ホーム画面にもどるなどで音が止まったときは、もどってきたときに、自動で再開する（これも未確認）。

### もう1つの開き方: 常駐ブリッジの URL（サーバーを動かさなくてよい）
常駐ブリッジ（ログインすると自動で動く）が、ゲームも配ります。**http://127.0.0.1:8765/game/** をブラウザで開くだけ（`sh tools/game.sh` は要りません）。リズム・コード編集は http://127.0.0.1:8765/ 。
ゲームを直したあとは、`sh tools/chordtoy_agent.sh update` で、常駐ブリッジ側のコピーを更新する（`sh tools/game.sh` のほうは、いつも最新）。

### 実機の盤をつなぐとき（任意）
1. 実機（ESP32）を USB でつなぎ、ブリッジ（`tools/midi_bridge.py`、常駐の LaunchAgent でも可）を動かしておく。
2. ゲームを開くと、自動で見つけて、HUD の「盤 画面 / 実機」ボタンが使えるようになる（押すと切り替わる）。
3. つながらなくても、ゲームは普通に動く（画面の盤）。
- ゲームのサーバーは、`/api/` をブリッジ（127.0.0.1:8765）に中継するだけ。**自分のパソコン（127.0.0.1）からしか、つながらない。**
- **ブリッジが ESP32 につながっていないとき**（Serial Monitor が使っている、USB が外れている など）: ゲームのタイトルの「実機:」ボタンに「ESP32 未接続（ここをクリックで、ブリッジを接続）」と出る。クリックすると、つなぎ直す。
- **音の出どころ**: ゲームを開いている間は、ブリッジが MIDI（GarageBand などへの出力）を止めるので、音はゲームからだけ鳴る。ゲームを閉じると数秒で元に戻り、これまでどおり GarageBand などで鳴らせる。
- ファームの書き込みは、VSCode の Upload ボタンでも `sh tools/upload.sh` でもよい（どちらも、ブリッジを止めてから書いて、再開する）。

| M | ミュート ON/OFF |

- 演奏は、位置 1→8 の順に、ループする。1つの位置 = 2拍。ドラムは、駒がなくても鳴る。盤の **1〜4番と5〜8番が、それぞれ1フレーズ**（技の判定で使う）。
- 「→」の駒は、前のコードをのばす。空きは休み（つながりが切れる）。
- 駒の形・色: 球 = 安定（トニック系）/ 立方体 = 広がり（サブドミナント系）/ 三角錐 = 緊張（ドミナント系）/ 八面体 = 色づけ・借用。

- **ジャッジ（2026-11-16 追加）**: 名前のついた技にならない並びにも、**ルール**で加点・減点・指摘する（ベースラインの階段 +60〜+120 / 機能のながれ +50・+30 / 導音の解決 +40 / なめらかな声 +40 / 進行感がない −40 / 唐突な借用和音 −30 / 役に立っていない駒は 0点の指摘（2026-11-24。第10弾で、−15 の減点をやめた。表示は残す）。同じ和音が続く = 「→」と同じ点・減点なし。内声の合計は +120 まで・加点 +320・減点 −160 まで）。右の「技」の一覧に、緑・赤・灰色の行で出る。加点は合計 +320（内声のぶんを足して、240 から）・減点は −120 まで。内声の半音の動き（2026-11-23 追加）: ガイドトーンの半音進行 +30（7度の音 → 3度の音）・半音で動き続ける内声 +40。**全部の条件は `docs/judge_report.md`**。最初のチュートリアル（ステージ0）では働かない。
- **メロディーにコードをつける（2026-11-17 追加。タイトルの「メロディーにコードをつける」。もとの名前は「合わせる」）**: 流れるメロディ（5つ。オリジナル）に、合う和音を1〜8番に置く。画面の上の「メロディの帯」に、メロディの音が、いまの和音に対して、どう聞こえるか（緑 = コードの音 / 水色 = テンション / 赤 = アヴォイド / 黄 = 不安定 / 灰 = 経過音）が、色で出る。**得点 = コード進行の点（技・ジャッジ）+ メロディとの相性の点（満点 1,200 + ボーナス）**。「できた！ 採点する」で、星（3つの条件）・ステップごとの表・お手本の一例が出る。ヒントも、メロディに合う和音だけを出す。**くわしくは `docs/melody_mode.md`**。
- **プリセット（2026-11-17 追加。上のバーの「☆ プリセット」。フリープレイとメロディのステージで使える）**: 気に入った進行を、**一部でも、ぜんぶでも**えらんで（上の8つのマスを、ドラッグ。1か所をクリック → 別の場所をクリック、でも範囲になる）、名前をつけて保存（30個まで。ブラウザの localStorage。「進み具合をリセット」では消えない）。下の一覧の「盤に置く」で、えらんだ場所（1〜8番）から置く（置く範囲の駒は、置きかわる。判定は、まとめて1回）。**実機の盤のとき**は、画面では置けないので、「案内を出す」→ 置く駒と場所が、ガイド・盤の矢印・駒の置き場の印で出る。名前の変更・削除（2回押し）もできる。P キーでも開く。
- **分割したマス（2026-11-23 追加。フリープレイ・タイムアタック・チャレンジステージ）**: 駒のあるマスの**左がわ・右がわに、駒を重ねる**と、そのマスが**前半・後半（1拍ずつ）**の2つに分かれて、半分の長さでコードが切りかわる（左 = 新しい駒が前半 / 右 = 新しい駒が後半 / まん中 = 置きかえ）。ダブルクリック・Delete・盤の外へのドラッグは、指した側の半分だけがはずれる。プリセットにも入る。くわしくは `docs/split_cells.md`。
- **リズム・コード編集の内容を、公開ページ（インターネット）のゲームに取り込む（2026-11-23 追加）**: 公開ページには、ブリッジがない。編集の画面（`http://127.0.0.1:8765/`）の「公開ページのゲームにも送る」で、**リンク**（開くと取り込みの確認が出る。スマホに送ってもよい）か**ファイル**を作る。ゲームの「リズムを取り込む」（タイトル・音のメニュー）に、貼り付けるか、ファイルを選ぶ。取り込んだものは、そのブラウザに保存される。
- **全部の端末の公開ページに、リアルタイムで届ける（2026-11-24 追加。設定が要る）**: リンクを一つずつ送らなくても、編集の画面で「ゲームに送る」と、公開ページのゲームを開いている**全部の端末**に、数秒以内に届く。Firebase Realtime Database（無料枠）を使う。**書きこむのは、この Mac のブリッジだけ**（`tools/cloud_sync.py`。秘密の鍵は、この Mac の中にだけ保存する）。公開ページは**読むだけ**（`game/js/net/cloud.js`。つなぎっぱなし + 読み直し。取り込みと同じ検査）。**最初の設定は、`docs/cloud_setup.md` のとおり**（Firebase のプロジェクト → ルール → 鍵 → 編集の画面に入れる → `game/cloud.json` の `url` に、公開してよい URL を書く）。`game/cloud.json` の `url` が空なら、何もしない。にせの Firebase で通しを確認ずみ（本物の Firebase では未確認）。
- **ループのつなぎ目（2026-11-18 追加）**: 盤が8つぜんぶ使われていて、**8番 → 1番**がつながっていると、進行系の技（強進行・ツーファイブワン・弱進行・半音下・裏コード・セカンダリードミナント）が成立して、加点される（囲みは 8番と 1番）。終止・固有進行は、つなぎ目をまたがない。
- **メロディをつける・書く（2026-11-18 追加。フリープレイの上のバーの「♪ メロディ」）**: 出来上がったコード進行に、**メロディを自動でつける**（なめらか・リズミカル・やさしい。テンションは **9th まで**。「別の案にする」で何通りでも）/ **ピアノロール**（DTM のような画面）で、メロディを**1から書く・直す**（空いているところをクリックで音を置く・ドラッグで動かす・右はしで長さ・右クリックか Delete で消す・矢印キー・元に戻す）。音の色 = いまの和音に対しての聞こえ方（メロディの帯と同じ）。上の「メロディの音 ON/OFF」で、鳴らす・鳴らさない。つくったメロディは、ブラウザに残る。くわしくは **`docs/melody_studio.md`**。
- **コードとメロディのプリセット（2026-11-18 追加）**: 「☆ プリセット」で、選んだ範囲の**コードと、そこにあるメロディを、いっしょに保存**できる（「メロディもいっしょに保存する」のチェック）。呼び出すと、駒が置かれて、**その範囲のメロディも置きかわる**（置く場所に合わせて、位置がずれる。メロディのないプリセットは、メロディをさわらない）。「♪ メロディ」の画面の「コードとメロディをプリセットに保存」からも保存できる。
- **sus4 の解決（2026-11-17 追加）**: Ⅴsus47 → Ⅴ（Ⅴ7）のように、4度の音（内声）が半音さがって3度の音へ動くと、ジャッジが +40（`docs/judge_report.md` の G5）。
- **音の高さ（2026-11-17）**: 標準の和音の高さを、**1オクターブ下げた**（ルートが C3〜B3。以前は C4〜B4）。`js/core/voicing.js` の `OCTAVE_DEFAULT`。
- **音の高さの計画（2026-11-24）**: 和音のルートの高さは、**ループ全体を見て、まとめて決める**（`js/core/voicing.js` の `planVoicing`。動的計画法）。最初のコードは本来の高さ。強進行は、完全4度上か完全5度下（進行全体の音域で決まる）。終止は、完全5度下を優先。**セカンダリードミナントの動き（Ⅲ7 → Ⅵm7・Ⅱm7 → Ⅴ7 など）は、完全4度上を優先**（2026-11-25。高くなりすぎるとき・Ⅰ系に解決するときは、5度下）。ループのつなぎ目（最後 → 最初）も計算に入れる（例: コンファーメーションは C3 C3 B2 E3 A3 A3 G3 C3）。ファームと同じ計算（`src/voicing.cpp`。実機には未書き込み）。くわしくは `docs/tricks_spec.md` の 0-2。同じ和音が続く = 「→」と同じ（点も高さも）。
- **ヒントの幅（2026-11-16 追加）**: おすすめ 4つ・発展 5つまで。前の駒からの「流れ」（Ⅴ→Ⅰ・Ⅱm→Ⅴ・Ⅵm→Ⅱm〈循環コード〉・導音・借用和音からの着地 など）、フレーズの終わり（3番・7番で Ⅴ を置いて、次を Ⅰ に）、ループのつなぎ目（8番 → 1番）、借用和音のヒントも出る。
- **チュートリアルのクリア**: 最後の駒を置いてから、**盤を見られる時間（7〜14秒）**のあとに、結果の画面が出る。結果の画面の「**盤面を見る・編集する**」を押すと、結果を閉じて、盤を自由にさわれる（下に「つぎへ ▶」「結果を見る」のバーが出る）。チュートリアルは、**進行の最後まで**（小室進行なら Ⅵm・Ⅳ・Ⅴ・Ⅰ、丸サ進行なら ⅣM7・Ⅲ7・Ⅵm7・Ⅰ7、Ⅳ-Ⅴ-Ⅵ進行は Ⅰ まで）置いて、クリアになる。ドミナント終止は、Ⅳ → Ⅴ → Ⅵm → Ⅴ を作る（Ⅳ-Ⅴ-Ⅵ進行のあとのステージ）。
- **偽終止は、Ⅵm（Ⅵm7）で終えれば成立**（前のコードは何でもよい）。Ⅴ のあとなら +50。
- **コードの難しさの加点**: 盤の上の「ちがう駒」ごとに、レベルに応じて +0〜+40（1回だけ）。
- **冒頭（1番）のドミナント系の駒は「？」**（2026-11-18 に変更）: Ⅴ系・ドミナント7th（Ⅲ7・Ⅰ7 など）・Ⅴ#dim7・Ⅵ（長三和音）を 1番に置くと、技にならず、コンボもとれず、100点の減点。**5番は減点しない**。ラグタイム進行（Ⅰ を2つぶん以上）・8小節ブルースなどは、冒頭でも認める。
- **自作コード・コードの編集（2026-11-23 追加。フリープレイだけ）**: 下の一覧の右はしの「＋」（Lv.5 の右・「→」の前の「自作」の段）から、**ピアノロール**で、自分のコードを作る（空いているところをクリック（タップ）で音を置く・ドラッグで上下に動かす・ダブルクリック（ダブルタップ）か × で消す・Delete・矢印キー・戻す/やり直す・鍵盤で音を聴く・「和音で聴く」「ばらして聴く」）。**名前は、構成音から自動で候補が出る**（例: E G# C D G → Eaug7(♯9)・A C E G B → Am9。読み方が複数あるときは、候補から選べる）。自分で名前をつけてもよい（「自動にする」でもどる）。**レベルは未設定でもよい**（未設定は、Lv.5 の右の「自作」の段。Lv. を決めると、その段に入り、「コードの難しさ」の加点がつく）。**もとの駒をもとにしてつくるコードは、もとの駒と同じレベルにはならず、はじめは「未設定」= 「自作」の段に並ぶ**（2026-11-24 夜から。編集画面に「もとの駒は Lv.2 ですが、同じ段には入れません」と出る。レベルを使いたいときは、編集画面で選ぶ）。**以前の版で保存した自作コードのレベルは、読み込むとき、一度だけ、すべて「未設定」にして、「自作」の段へ移す**（もとの駒をもとにしたかは、保存からは分からないため。移した数は、知らせが出る。レベルは、編集画面で選びなおせる。保存の `chordbook.lvRule` = 2 で、一度だけ）。駒の**色・形**（働きにまかせる・球・立方体・三角錐・ひし形・円柱・星・わ）も選べる（見本が出る）。**もとの駒は、上書きされない**（2026-11-24 から）: 駒を右クリック（スマホは長押し）・「コードを編集」→「これをもとに自作コードをつくる」と、もとの構成音から編集画面が始まり、保存すると、**新しい自作コードとして、「自作」の段に足される**（音を足してテンションをつける・まったく別のコードにする。もとと同じ構成音のままなら、「同じコードがあります」と、保存できない）。以前の版で、もとの駒を編集して保存していたものは、**起動したときに、自作コードに引っ越す**（もとの駒は、もとのまま）。**DTM の画面（このコードの編集・メロディ）は、ドラッグで、音をまとめて選べる**（空いているところから四角でかこむ。Shift・Ctrl/⌘ で選びたす。スマホは「範囲選択」ボタン。まとめて動かす・長さを変える・消す・Ctrl/⌘ + A）。保存は**ブラウザ**（localStorage）。ゲームを立ち上げ直しても残り、「進み具合をリセット」でも消えない。**削除**は、駒の右クリックのメニュー（2回押す）か、編集画面から。**進行の判定は、駒の「ルート」と「種類」で動く**ので、自作・編集した駒も、技・ジャッジ・ヒントの対象（種類は、構成音から決まる。テンションは種類を変えない）。自作コードは、チュートリアル・チャレンジ・メロディのステージでは、見えない。プリセットには、名前で入る（あとで削除すると、呼び出すとき、その駒だけ空きになる）。**実機の盤の駒は、自作コードにはならない**（タグがないので、画面の盤だけ）。
- **技の詳細と、使われている曲（2026-11-23 追加）**: 技の枠・一覧の行・「理由」の「くわしく」から開く。固有進行には、**その進行が使われている曲**（できるだけ日本の曲。曲名とアーティスト名だけ。歌詞・メロディは出さない）。ウェブの解説・Wikipedia に載っていた例だけで、**耳では確認していない**。日本の曲の例を確認できなかった進行は、そう書いて、洋楽・クラシックの例を出す。出典・調べた日は `docs/songs_sources.md`。
- **ヒント（2026-11-23 の調整）**: ① **Ⅱm7** は、フレーズの頭（1番・5番）で、いつも「おすすめ」に出る（ほかの位置でも、前がトニック系・サブドミナント系なら、発展に）。② **セブンスコード優先**: 同じルートの「3和音とそのセブンス」（Ⅴ と Ⅴ7 など）が並んだら、セブンスを選ぶ。左の駒にセブンスがあるときは、とくに（Ⅰ系と、解決先の Ⅵm は、3和音のままでもよい）。
- **ヒントの自然さ（2026-11-24 第10弾。ご指摘: 「Ⅲ7 のあとの第一候補が Ⅵ（長三和音）だけ」「Ⅵm7 がない」「不可解な候補が多い」）**: 候補に、**「自然さ」**（level 0〜3。`core/continuation.js`）のものさしをかけた。ふつうの和音どうしは **Piston『Harmony』の「ふつうの根音進行の表」**（Ⅰ・Ⅱ の行は紹介文で確認。ほかは記憶。`docs/theory_audit.md` の10章）・色のついた和音（セカンダリードミナント・借用和音・裏コード・経過のディミニッシュ・サス）は「どこへ向かうか・どこから来るのが自然か」の決まり。**ルートの動きだけが当たった候補・先読み・流れのヒントは、自然なものだけ**（Ⅲ7 → Ⅲ♭m6・Ⅴ7 → Ⅳ#m7♭5 などは出ない）。**同じルートの和音は、その場面で自然なもの**を選ぶ（Ⅲ7 のあとは Ⅵm7。Ⅵ（長三和音）は、4番・8番の、ピカルディ終止のときだけ）。ちがう働きの和音（Ⅵm7 と Ⅵ7・Ⅴ7 と Ⅴsus47）は、発展にもう1つ出す。いつも続く和音（Ⅲ7 → Ⅵm7・Ⅱm7 → Ⅴ7 など）は、技にならなくても、**おすすめ**に入る。おすすめが4つをこえたぶんは、発展に回る（つぶさない）。終止の形は、4番・8番でだけ「技が決まる」と勧める。借用和音（♭Ⅵ・♭Ⅶ・♭Ⅱ）は、3番・7番だけ。
- **ループの指摘（2026-11-23）**: 8番の駒が Ⅴ7 のようなドミナントなのに、つなぎ目（8番 → 1番）が技にならないとき（1番が空き・1番が Ⅰ 系でない・1番が「？」）、その**理由**を、0点の指摘で出す（「ジャッジ」の行）。
- **和音のつなぎ方（2026-11-24 追加。「♪」のメニューの4行目）**: **ふつう** / **スムーズ（中）** / **スムーズ（大）**。スムーズは、前の和音の、実際に鳴っている音から、次の和音の音を、**できるだけ動かさずに**つなぐ（内声の動きが、最小）。中 = ルートが**完全4度・5度**で動くつながりだけ（Dm7 → G7 → CM7 = DFAC → G + DFGB → CEGB。**ルートの G は、別にベースとして置く**ので、5つの音が鳴る）。大 = **全部の動き**。最初の和音はふだんの高さ・ループのつなぎ目も動きが少なくなるように選ぶ。計算は動的計画法（`core/voicing.js` の `planSmoothVoicing`）。**ゲームの音だけ**（実機のファームは、まだ、ふつうのまま）。
- **低すぎる進行は、1オクターブ上げる（2026-11-24 追加）**: 和音の音（別のベースを含む）に **C1（MIDI 36）以下**があれば、進行ぜんぶを 1オクターブ上げる（`voicing.js` の `LOW_LIMIT`。基準は、あとで変えられる。バッキングのベースの音は、数えない）。
- **「♪」のメニュー（上のバー）**: 音色（ピアノ・エレピ・ギター・オルガン・ストリングス・ドライブシンセ〈拍の頭で引っ込み、裏拍から、ゆっくり・強く「ズァアッ」と立ち上がる「サイドチェイン」〉・ベル）・ビート・バッキングを選べる。選んだものは、ステージの標準より優先（「ステージの標準にもどす」で戻る）。ステージごとの標準は `stages.js` の `instrument` / `drumId` / `backingId`。
- **リズム・コード編集の画面（http://127.0.0.1:8765/）から、名前をつけて送れる**: 「ゲームに送る」で、ドラム・バッキング（「♪」のメニューに増える）と、進行（駒を2〜8個。図鑑に新しい技として増える）が、**ゲームを開いたままで、すぐ届く**（`/api/library`。仕様は `docs/tricks_spec.md` の 6-3）。
- 駒を置いたときの試聴（実機の盤でも）は、**演奏中は小さく・短く**鳴る（演奏中のコードと、ぶつからないように）。ESP32 のブザー（アルペジオ）は、ブリッジがつながっている間は鳴らない。

## 直す・足す

- **技の点数・条件を直す** → `js/core/tricks.js` の `PATTERNS`（条件・点・優先度。`startAt` = 1番・5番から、`end: 'phrase'` = フレーズの終わりで）/ `TRICKS`（名前・色・説明・`group` = 仲間）/ `SCORE`（倍率・「？」の減点）。`docs/tricks_spec.md` も更新する。
- **ステージを足す** → `js/game/stages.js` の `STAGES` に、`id`・`goal`・`pieces`・`solution`（お手本）・`intro`/`outro` を足す。案内の矢印は solution から自動で作られる。`id` は保存に使うので、変えない。
- **駒を足す・直す** → ファーム `src/chords.cpp`（正）。そのあと `sh tools/game_lab/gen_game_data.sh` で JSON を作り直す。`tools/host_tests/test_chords.cpp` の期待値も直す。**ID 1〜28 の意味は変えない**（登録済みのタグが使っている）。
- **音・ドラムの型** → ファーム側（`src/rhythm.cpp`）が正。`gen_game_data.sh` で `presets.json` を作り直す。
- **メロディを足す・直す** → `js/game/melodies.js` の `SOURCES`（メロディは `E5:4 G5:4 | …` の文字。音名:長さ（マス。1ステップ = 8マス）。お手本 `answer` と説明も）。点数・判定の決まりは `js/core/melody.js`。`id` は保存に使うので、変えない。足したら、`docs/melody_mode.md` の表も更新する（自動テストが、データの長さ・音域・お手本の相性を確かめる）。
- **自動メロディのルール・作風** → `js/core/automelody.js`（`CELLS` = リズムの型 / `STYLES` = 作風 / `AUTO` = 音域・9th の上限・何通りから選ぶか / `tasteScore` = できばえの式 / `checkRules` = 決まりの検査）。`docs/melody_studio.md` も更新する。
- **ドライブシンセの立ち上がり・歪み** → `js/audio/instruments.js` の `PUMP_ONSET` / `PUMP_POWER`（立ち上がり）、`DRIVE_K` / `DRIVE_BIAS`（歪み）。

## 既知の限界（試作）

- 音の質は、耳で確認していない（数値の確認のみ。ピーク 0.90 で、割れない）。メロディの音（笛のような合成音）・ドライブシンセの新しい立ち上がり・歪みも、耳では未確認。
- 実機の盤との接続は、**ニセの ESP32 + 本物のブリッジ**でのみ確認。本物の ESP32 では、未確認。
- 新しい駒「Ⅱ♭7」は、ファームに追加しただけで、まだ書き込んでいない。実機で使うには、書き込みと、新しいタグの登録が要る。
- 点数・ステージの内容・文章は、仮。遊びながら調整する。
- 対戦モードは、まだない。
- メロディの採点・プリセットは、パソコン上のテストと、画面の確認のみ。実機の盤（本物の駒）で遊んだときの手応えは、未確認。
- **自動でつけたメロディの「センス」は、耳では確認していない**（ルールの検査と、数値の確認のみ。834 通りで、決まりの違反 0・和音との相性は平均 98%）。
- **Chrome 以外（Safari など）は未確認。スマホ（iPhone）は、本物では、動かしていない**（Chrome のスマホ表示で確認。消音スイッチ・画面を消したあとの音の再開・指の感触・描画の重さは、実機で確かめる必要がある）。
