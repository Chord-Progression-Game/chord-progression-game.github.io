# CHORD LINES（仮題） ゼミ進捗 11/18

## これは何か
和音（コード）が書かれた駒を盤に並べて、曲の「コード進行」を作るゲーム。コード進行は和音を並べた順番のことで、曲の雰囲気はこの順番でほぼ決まる。

並べ方には「王道進行」「小室進行」みたいな定番の型がある。このゲームは、そういう特徴のあるつながりを、スケボーのトリックみたいに判定する。決まるとその部分が光って、名前が出て、点が入る。音楽の知識がなくても、置いて聴いて、技を集める感覚で遊べるようにするのが狙い。

- 盤は8マス。1から8の順にループして鳴る
- 駒の形で和音の働きが分かる（球は安定、立方体は広がる、三角錐は緊張）
- ゲーム本体はパソコンで動く（Web・3D）。駒をのせると読み取る実物の盤にもつなげられる

## 前回のフィードバックと、やったこと
**「選んだ後の結果だけでは判断材料にならない」**
→ 置く前に、次に置く候補が薄く出る「ヒント」を作った。なぜおすすめかも文で出る。あと最初に、技を1つずつ覚えるチュートリアルを14ステージ作った。説明はなるべく音楽用語を使わない言葉にした。

**「得点の基準がないとモチベーションがない」**
→ 技ごとに点を決めた。技がつながるとコンボで倍率がつく。技にならない並びも、流れが自然かどうかをルールで見て、加点か減点をする。右の欄に「なぜこの点か」の理由が出る。点数はまだ仮。

**「早くプロトタイプでビジュアルを見せたい」**
→ 3Dの盤と駒を作った。技が決まると囲みと名前が出る演出つき。

**「タイトル画面からのフローチャートを作る」**
→ 3枚作った（画面の流れ、1回の操作で起きること、全体の仕組み）。

**「ランキング？ノルマ？誰かに聞かせたい」**
→ これはまだ。代わりに、聞かせたいものを作る土台として、気に入った進行を保存する機能とメロディをつける機能を作った。対戦とランキングはこれから。

## 今週やったこと

### 遊べる形になった
- 技は23個。「つながり」「曲の終わり方」「定番の進行」「別の調から借りてきた和音」の4グループ
- 遊び方は4つ。チュートリアル、フリープレイ（自由に並べる）、チャレンジ（90秒で高得点）、「合わせる」（流れるメロディに合う和音を置く）
- 音色やドラムのパターンを切り替えられる

### 音楽理論の見直し
技の定義をネットの資料で確かめ直した。曲の終わり方の1つ（ピカルディ終止）の定義が間違っていたので直した。あと、定番の進行は決まった位置から並べたときだけ成立、曲の頭に不自然な和音を置くと減点、のようにルールを整理した。

### メロディ機能（新）
メロディは歌う部分のこと。コード進行だけだと伴奏だけなので、上にメロディをのせたくなる。

- 自動でつける: コード進行に合うメロディをパソコンが作る。和音に合う音を目立つ拍に置く、急に大きく跳ばない、最後は落ち着く音を長く伸ばす、などのルールで作る。AIの学習ではなくルール。何通りか作って良さそうなものを選ぶ。気に入らなければ「別の案」で作り直せる
- 直す・書く: ピアノの鍵盤が縦に並んだ画面（DTMでよくあるやつ）で、音をクリックして置く、動かす、消す。音は色で、和音に合っている（緑）、ぶつかる（赤）などが分かる。ゼロから書くこともできる
- 保存: 和音とメロディをセットで名前をつけて保存して、あとで呼び出せる
- 確認: 834通りの進行で試して、ルール違反は0。和音との相性の点は平均98%。ただし良い曲かどうかは別の話

### 実物の盤（駒の読み取り）
駒をのせてから反応するまでが遅いのと、たまに勝手に外れた扱いになるのが問題だった。

- 読み取り1周が約270ミリ秒から約141ミリ秒になった（ほぼ半分）
- 26分間、駒を動かさずに置いたままにして、勝手に外れた扱いになったのは0回
- 盤の駒がゲーム画面に出ることを確認した
