# 全部の端末に、リアルタイムで届ける設定（Firebase）

リズム・コード編集の画面（自分の Mac）で作った、ドラム・バッキング・進行を、**リンクを送らずに**、公開ページ（GitHub Pages）のゲームを開いている**全部の端末**（パソコン・スマホ）へ、すぐ届ける仕組みです（2026-11-24）。

**状態: 部品はできていて、「にせの Firebase」を使ったテストでは、通しで動きました（編集画面で送る → 0.4秒ほどでゲームに届く）。本物の Firebase とは、まだ、つないでいません。** 下の手順で、最初の設定を、お願いします。設定をしなければ、これまでどおり動きます（自分の Mac のゲームには、いつもどおりリアルタイムで届く・公開ページには、リンクかファイルで取り込む）。

## しくみ（ざっくり）

```
編集画面（Mac）──「ゲームに送る」──▶ ブリッジ ──書きこむ──▶ Firebase Realtime Database ──変わった瞬間に届く──▶ 公開ページのゲーム（全端末）
                                       （秘密の鍵は、ここだけ）          （読むのは、だれでも）               （読むだけ。書きこむ道はない）
```

- **書きこめるのは、この Mac のブリッジだけ**です（秘密の鍵を持っているため）。
- 公開ページのゲームは、**読むだけ**です。読んだ内容は、リンクの取り込みと同じ厳しさで検査します（動くコードは、受け取りません。名前・長さ・数の上限・知らない駒は、はじきます）。
- つなぎっぱなしの通信（EventSource）で、変わった瞬間に届きます。切れたときは、数秒ごとに読み直します（ポーリング）。前に届いた内容は、端末に保存してあるので、つながらない場所でも使えます。

## 用意するもの

- Google のアカウント（Gmail など）
- 無料のプラン（Spark）で足ります。ライブラリは、数十 KB の小さな文字データです。同時につなげる人数・転送量などの上限が、無料の枠にはあります。**数字は、Firebase の料金ページで、確かめてください**（私は、公式の最新の表を、確認していません。目安として、同時接続 100 人ほど）。

## 手順

画面の名前は、Firebase の更新で、少し変わることがあります。見つからないときは、近い名前のものを探してください。

### 1. プロジェクトを作る

1. https://console.firebase.google.com/ を開いて、Google のアカウントでログインします。
2. 「プロジェクトを追加」（または「プロジェクトを作成」）を押します。
3. 名前を入れます（例: `chord-lines`）。Google アナリティクスは、**オフ**で、かまいません。
4. 「プロジェクトを作成」を押して、できあがるのを待ちます。

### 2. Realtime Database を作る

1. 左のメニューの「構築」（または「Build」）→「Realtime Database」を開きます。
2. 「データベースを作成」を押します。
3. 場所（ロケーション）を選びます。日本からなら、**シンガポール（asia-southeast1）**が近いです（選べる場所は、画面に出るものから）。
4. セキュリティのルールは、「**ロックモードで開始**」を選びます。次の手順で、ルールを書きかえます。
5. できあがった画面の上に、データベースの **URL** が出ています。たとえば `https://chord-lines-default-rtdb.asia-southeast1.firebasedatabase.app` です。**これを、コピー**しておきます。

### 3. ルールを書く（読むのは、だれでも・書くのは、鍵を持つ人だけ）

1. Realtime Database の画面の「ルール」のタブを開きます。
2. 中身を、次のものに**ぜんぶ書きかえて**、「公開」を押します。

```json
{
  "rules": {
    "chordlines": {
      "library": {
        ".read": true,
        ".write": false
      }
    }
  }
}
```

- `.read: true` … だれでも読めます（公開ページのゲームが読むため）。
- `.write: false` … ふつうの人は、書きこめません。ブリッジは、サービスアカウントの鍵（管理者の権限）で書くので、このルールの影響を受けずに、書きこめます。

### 4. 書きこむための鍵をもらう

1. 左上の歯車 →「プロジェクトの設定」→「サービス アカウント」のタブを開きます。
2. 「新しい秘密鍵を生成」を押します。JSON のファイルが、ダウンロードされます。
3. **このファイルは、パスワードと同じです。**
   - GitHub のフォルダ（`Chord-Progression-Game`）の中には、**置かないでください**（公開されます）。ダウンロードのフォルダのままで、かまいません。
   - 人に送らない・画像にして貼らない。
   - 設定が終わったら、ダウンロードしたファイルは、消してかまいません（ブリッジが、この Mac の中に、別に保存します）。

### 5. 編集画面に入れる

1. Mac で、ブリッジが動いている状態で、リズム・コード編集の画面（http://127.0.0.1:8765/ ）を開きます。
2. 「ゲームに送る」の下の、「**全部の端末の、公開ページのゲームへ、自動で送る（リアルタイム）**」の欄に、
   - 「データベースの URL」に、2 の 5 でコピーした URL を貼ります。
   - 「鍵」で、4 でダウンロードした JSON のファイルを選びます。
3. 「つなぐ（書きこめるか確かめます）」を押します。
4. 「つながりました」と出れば、成功です。このときに、1回、書きこんで確かめます（Firebase の「データ」のタブに、`chordlines` → `library` が現れます）。

鍵は、この Mac の `~/Library/Application Support/ChordToy/cloud.json` に、自分だけが読める設定（chmod 600）で、保存されます。画面・ブリッジのログ・ゲームのファイルには、出ません。

### 6. 公開ページに、URL を教える

1. このフォルダの `game/cloud.json` を開きます。
2. `url` に、同じ URL を書きます。

```json
{
  "url": "https://chord-lines-default-rtdb.asia-southeast1.firebasedatabase.app",
  "path": "chordlines/library"
}
```

3. GitHub Desktop で、コミットして、プッシュします（`main` へのプッシュで、公開ページが、自動で更新されます）。

**URL は、公開されて、かまいません**（読む側の入り口です）。**秘密の鍵は、ここに書かないでください。**

### 7. 確かめる

1. 編集画面で、ドラムかバッキングを作って、名前をつけて「ゲームに送る」を押します。
2. スマホなどで、公開ページのゲームを開きます。「リズムを取り込む」の画面に、「つながっています」と出て、送ったものが、一覧に出ます（音のメニューのドラム・バッキングにも増えます）。
3. 編集画面で、もう一度送る（または削除する）と、**開いたままのゲームに、数秒以内に**、反映されます。

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 「つなぐ」で、エラーが出る | URL の形（`https://` で始まって、`firebaseio.com` か `firebasedatabase.app` で終わる）/ JSON のファイルが、Firebase でもらったものそのままか |
| 「つなぐ」は成功するが、データが現れない | ルールが「公開」されているか（保存だけして、公開を押していないことがあります） |
| 公開ページに、何も届かない | `game/cloud.json` の `url` が、空でないか / コミット・プッシュしたか / 公開ページを読み込み直す（⌘R・スマホは、タブを閉じて開き直す） |
| 一部だけ届かない | 名前が長すぎる・数の上限（ドラム 40・バッキング 40・進行 60）・ゲームにない駒を含む進行は、はじきます（取り込みと同じ検査） |
| 止めたい | 編集画面の「自動で送るのを、やめる」（この Mac に保存した鍵も消えます。公開ページに、すでにあるものは、そのまま残ります） |

古い方式の「Database secret」（データベースのシークレット）でも書きこめます。ただし、新しいプロジェクトでは、見つからないことがあります。サービスアカウントの JSON を、おすすめします。

## 安全について

- 公開ページに出るのは、**ライブラリ（ドラム・バッキング・進行の名前と中身）だけ**です。個人の情報・鍵は、含みません。ただし、**読むのは、だれでも**なので、パターンの名前に、人に見せたくない言葉は、入れないでください。
- 鍵（サービスアカウントの JSON）をなくしたとき・人に見せてしまったとき: Firebase の「プロジェクトの設定 → サービス アカウント」から、その鍵を無効にして、新しく作り直します（Google Cloud の「IAM と管理 → サービス アカウント → キー」からも、消せます）。
- ルールを `.write: false` にしてあるので、公開ページ（ゲーム）や、ほかの人は、書きこめません。ゲームのプログラムには、書きこむ道が、ありません。

## 確かめたこと・まだのこと

**確かめたこと（にせの Firebase = `tools/host_tests/mock_firebase.py` での、自動テスト）**
- 鍵の検査（形・URL・合わない鍵はことわる）・保存（chmod 600）・画面・ログ・エラーの文に鍵が出ないこと
- OAuth2（サービスアカウントの署名つきの JWT → アクセス トークン）の作り方（署名は、にせ側が openssl で確かめる）
- 変更があると、自動で送る・続けて変わったときは、まとめる・失敗したら、あとでやり直して追いつく
- ゲーム側: つなぎっぱなしで受け取る・切れてもポーリングで追いつく・形が違うものは、使わない・前に届いたものを、つながらなくても使う
- 通し: 編集画面で送る → ゲーム（本物の Chrome）の音のメニュー・図鑑に、約 0.4秒で届く
- テスト: `python3 tools/host_tests/test_cloud_sync.py` / `python3 tools/host_tests/test_cloud_game.py` / `python3 tools/host_tests/test_editor_pages.py`

**まだ（本物では、確かめていないこと）**
- 本物の Firebase と、つながるか（URL・ルール・認証の細かい違い。画面の名前の違い）
- 本物の回線での、遅れ・つなぎ直し・同時接続の上限
- 本物の GitHub Pages（https）のゲームが、Firebase から受け取れるか
- スマホ（iPhone の Safari）での、つなぎっぱなしの通信（バックグラウンドに回ったときの切れ方）。切れても、開き直したときに、読み直します
