# 単体化の計画 — Mac なしで動く製品にするには

作成: 2026-10-19 ／ 対象: `ESP32_Octo_01`（RC522 8台版）

「`sh tools/run.sh --gm` を毎回打たずに GarageBand から鳴らしたい。最終的には、Mac をつながなくても、この製品だけで今までの機能を再現したい」
— この要望に対して、**何が必要で、何が実現できるか**をまとめます。

各項目に、確かさを付けました。

| 印 | 意味 |
|---|---|
| **[実測]** | この基板（ESP32-S3、2026-10-19）で、実際に測った・動かした |
| **[調査]** | 資料・製品ページで調べた（この機材では未確認） |
| **[未確認]** | まだ確かめていない。または、私には確かめられない（耳で聞く、など） |

## 0. 先に結論

1. **GarageBand を、ターミナルなしで鳴らす方法はあります（USB-MIDI）。ピアノとドラムを同時に鳴らす方法も、複数あります（2-5）。**
   - ESP32 の「USB側」のポートを、MIDI 機器として Mac に見せます。ファームは実装済みです。**[未確認]**（2本目のケーブルを挿して試す必要があります）
   - GarageBand は、選んでいる1つのトラックに全チャンネルをまとめて入れるため、ふつうの音源（ピアノなど）に切り替えたままドラムを足すと、低い音になります（README 6-5）。
   - ただし、**トラックの音源を「複数のチャンネルを別々に鳴らせる音源」に替えれば、解決する見込み**があります（Apple の GM 音源 `DLSMusicDevice`。この Mac に入っており、検証にも合格）。5分で試せます（2-5）。
2. **Mac なしの単体化は、実現できます。** 音を出す部分が最大の課題でしたが、**この基板だけで、ピアノとドラムを作れる**ことを、実測で確かめました。**[実測]**
   - GM 音源の実物（グランドピアノ + ドラム）を、この基板で動かし、**Mac が作る音と、波形が（1/32768 の誤差で）一致**しました。
   - 計算は、CPU 1コアの約 24%（44.1kHz）で足ります。残りは、読み取り・Wi-Fi・表示に使えます。
3. **足りないのは、部品2つと、ソフト3つです。**
   - 部品: ① I2S アンプ（約 1,100〜1,600 円）+ ② スピーカー。
   - ソフト: ① 音源をファームに組み込む ② 操作画面を Wi-Fi 経由で ESP32 自身が配る ③ 駒の登録を画面から行う。
4. **おすすめの進め方**: まず `docs/audition/` の3つの音を聞いて、音質を確かめる（0円）→ USB-MIDI で Mac 直結を試す（0円）→ アンプとスピーカーを買う（約 3,000 円）→ ソフトを組み込む。

## 2. 音（いちばん大事なところ）

### 2-1. 実測したこと

測定用プログラムは `tools/sound_lab/` に入れてあります（再現できます）。アンプは未接続なので、**音は出していません**。計算の速さ・メモリ・リアルタイムに間に合うか、だけを測りました。

**この基板**: ESP32-S3、240MHz、2コア。フラッシュは**実物 16MB**（PlatformIO の設定上は 8MB で、残りの 8MB が未使用）。PSRAM 8MB。**[実測]**

**(a) 自作の軽いサンプル再生エンジン（録音した音を、音程を変えて鳴らすだけの最小構成）** **[実測]**
- 1つの音を1フレーム作るのに、20 サイクル（内蔵RAM）〜27（PSRAM）〜30（フラッシュ）（約 0.1µs）。音データがどこにあっても、大差ない。つまり、**音データを展開せず、フラッシュから直接読んで鳴らせる**。
- 44.1kHz で 32 声: CPU 1コアの 12〜16%。リバーブ（響き）を足しても +3% 弱。
- I2S（音の出力回路）に流し続けながら、もう一方のコアで重い処理（読み取りの代わり）を回しても、**8秒間、ずれ 0.0%・途切れなし**（サンプル 32 声 + FM 8 声 + リバーブ、44.1kHz。1回の計算は平均 1.3ms、制限は 5.8ms）。

**(b) 既製の SF2 音源エンジン（TinySoundFont、MIT ライセンス）に、本物の GM 音源データを載せる** **[実測]**
- 音源データ: GeneralUser GS から、グランドピアノ + 本機が使うドラム8種だけを取り出した **3.1MB**（`tools/sound_lab/sf2trim.py`）。フラッシュに書き込み、PSRAM に展開。展開に 4.4 秒、PSRAM を 6MB 使う。
- **音の一致**: あなたの8枚の駒の演奏（ドラム + アルペジオ、20.5秒）を ESP32 の中で作って、Mac の結果と比べました。**波形 1024 フレームで最大の差が 1（満点 32767）**、0.5秒ごとの音の大きさ 41 点も、最大 0.19% の差でした。
- **速さ**（同時発音は最大 9〜10 声）:

| 条件 | 44.1kHz | 22.05kHz |
|---|---|---|
| そのまま | 1コアの 131%（**間に合わない**） | 59% |
| 2か所を直す（下記） | **24%**（4.2倍速） | 12.5% |

- 直したのは2か所です（`tools/sound_lab/esp32_tsfbench/tsf_esp32_speedup.patch`、67行）。ESP32-S3 には**倍精度（double）の計算回路がなく**、1回の足し算でも数百サイクルかかります。TinySoundFont は、音の位置とフィルターに double を使っていたので、前者を整数（固定小数点）に、後者を float に変えました。
- **リアルタイム試験**（I2S に流し続け、もう一方のコアで重い処理を回しながら、44.1kHz・256フレームずつ）: **遅れたチャンク 0 個**。

**(c) 音源データの大きさ** **[実測]**（GeneralUser GS の中身を数えた）
- グランドピアノ: 2.17MB ／ エレピ（Tine）: 0.37MB ／ 本機が使うドラム8種: 0.91MB（標準のドラムキット全部だと 2.82MB）。
- フラッシュ 16MB に十分入ります。

### 補足: MAX98357A（I2S アンプ）には、スピーカーが別に必要です

MAX98357A は、音のデータ（I2S）を、スピーカーを鳴らせる大きさの信号にする**アンプだけ**の基板です。**スピーカーは付いていません**。出力の端子（+ と −）に、4〜8Ω・3W くらいの小さなスピーカーを、別に買って、つなぎます（価格は未調査）。
- 小さなスピーカー（直径 28〜40mm）をむき出しで鳴らすと、**音が薄く、安っぽく聞こえます**。箱（筐体）に入れて、もう少し大きなもの（50mm 以上）にすると、低音が出て、聞こえ方が大きく変わります。**スピーカーと箱は、音質の大きな部分です**。
- スピーカー内蔵の音源ユニット（Unit Synth）は、8Ω 1W の小さなスピーカーが付いています。
- ヘッドホンや、手持ちのスピーカー（アンプ内蔵）につなぐなら、アンプでなく、**I2S の DAC（PCM5102 など）**を使います（ライン出力）。まず手持ちの機材で音質を確かめたいときに向いています。

### 2-2. 方式の比較

| | **A. ESP32 の中で作る**（おすすめ） | **B. 音源モジュールを足す**（保険） | C. 小さな Linux ボードを入れる |
|---|---|---|---|
| 仕組み | ESP32 が音を計算 → I2S アンプ → スピーカー | ESP32 が MIDI を UART で送る → SAM2695 → スピーカー | Raspberry Pi 等で FluidSynth |
| 買うもの | I2S アンプ + スピーカー | M5Stack Unit Synth（スピーカー内蔵） | 基板 + SD カード + アンプ |
| 値段 [調査] | アンプ 1,130〜1,551 円（スイッチサイエンス）+ スピーカー | 2,453 円（スイッチサイエンス、U178） | 未調査 |
| ESP32 のピン | **3本**（I2S） | **1本**（UART の送信） | 少 |
| 追加のソフト | 大（音源の組み込み） | **小**（いまの MIDI のバイト列を UART に出すだけ） | 小〜中 |
| 音の自由度 | 高い（音色データを選べる・差し替えられる） | GM の128音色 | 高い |
| 起動 | 数秒（TinySoundFont のままだと展開に 4.4 秒） | すぐ | 十数秒以上かかるのが普通 **[未確認]** |
| 未確認 | 耳で聞いた音、アンプ接続、Wi-Fi 同時動作 | 耳で聞いた音 | 起動時間、電源断への強さ |
| 評価 | 実測で見通しが立った。**本命** | 手早く音を出す保険。音質は聞いてみないと分からない | 製品体験（すぐ鳴る・電源を切れる）で不利 |

- B の根拠 **[調査]**: SAM2695 搭載。M5Stack Unit Synth（U178）は、5V、UART 受信（MIDI 規格の 31250 baud。M5 のライブラリ定数 `UNIT_SYNTH_BAUD`）、8Ω 1W のスピーカーと NS4150B アンプが内蔵、同時発音 64（エフェクトなし）、128 音色。ドラムはチャンネル10 のまま鳴る。
- A の根拠 **[調査]**: ESP32-S3 でサンプラーを動かした例が複数ある（SD から読む方式で 15〜20 声、44.1kHz ステレオ。`copych/ESP32_S3_Sampler`）。TinySoundFont でピアノだけに絞った例もある（`lego-piano`）。
- 私は、**A を本命、B を保険**にするのがよいと考えます。理由: 測定で見通しが立った / 部品が少ない / 音色を自分で選べる / 将来の機能（音色切り替えなど）が足しやすい。B は、A で行き詰まったときに、1週間以内に「単体で鳴る」状態にできる保険です。

### 2-3b. 音質の改善（「おもちゃのように聞こえる」というご指摘を受けて、2026-10-19）

聞こえ方が安っぽくなる原因は、3つ考えられます。**どれが効いているかは、私には聞こえないので、聞き比べで確かめてください。**
1. **響き（リバーブ）がない**: 最初の試聴は、ドライ（響きなし）でした。ESP32 の中でもリバーブは動かせます（実測: 1コアの 3% 弱）。
2. **音源データが小さい**: GeneralUser GS のピアノは、約2MB。**本物のグランドピアノ（Yamaha C5）を録った Salamander Grand Piano** は、はるかに大きい（全部で数GB）。
3. **エレピ（GM の Tine）が素朴**: 録音のエレピでなく、計算で作る FM 方式も試す。

聞き比べ用に、同じ演奏（あなたの8枚の駒、ドラム2番・バッキング6番）を、**すべて響きつき**で4通り作りました（`docs/audition/`）。ドラムは共通です。

| ファイル | ピアノ／エレピの音源 |
|---|---|
| `A_generaluser_piano_reverb.m4a` | 前と同じ GeneralUser GS のピアノ + リバーブ（響きだけの効果を聞くため） |
| `B_salamander_piano_reverb.m4a` | **Salamander Grand Piano**（Yamaha C5 の本物の録音。29音を、中くらいの強さで録ったもの） + リバーブ |
| `C_generaluser_epiano_reverb.m4a` | 前と同じ GeneralUser GS のエレピ + リバーブ |
| `D_fm_epiano_reverb.m4a` | **FM 方式のエレピ**（録音を使わず計算で作る。ローズ風の「ティン」と、ゆっくり減る本体、左右のゆれ） + リバーブ |

- 作り方は `tools/sound_lab/mix_compare.py`。音程は、ドレミで確かめました（Salamander・FM とも、ずれ ±3 cent 以内 [実測]）。
- Salamander の権利: CC-BY 3.0（Alexander Holm）。**表示（クレジット）が必要**。商用も可。[調査]
- **ESP32 に入れる大きさ**（Salamander を 1段階の強さだけ、モノラルにして、各音を最初の数秒だけ残す。[計算]）:

| 条件 | 16bit | ADPCM（4bit。音は少し荒くなる） |
|---|---|---|
| 各音 3秒・32kHz | 5.6MB | 1.4MB |
| 各音 4秒・32kHz | 7.4MB | 1.8MB |
| 各音 6秒・44.1kHz | 14.7MB | 3.7MB |

  - フラッシュ（実物 16MB）には入る。ただし、**本物のピアノは強さごとに音色が変わる**ので（Salamander は16段階）、強さの段階を増やすほど、大きくなる。
  - **microSD カードから流し込む方式**なら、数GBでも使える。**この基板には microSD スロットはありません**（訂正: 写真で確認。以前の記述は別の Freenove 基板の資料の取り違えでした）。外付けの microSD モジュール（SPI か SDMMC 1bit）を、空きピンにつなぎます。ESP32-S3 で、SD から流しながら 15〜20声（44.1kHz ステレオ）を鳴らした例がある [調査: `copych/ESP32_S3_Sampler`]。課題は、音の立ち上がりの遅れ（先頭の部分をメモリに置いて隠す）と、SD のピン（3〜4本）の追加。
  - いまのエンジン（TinySoundFont）は SF2 形式だけ。Salamander を使うなら、**自作の軽いエンジン**（2-1 で測った、1フレーム 20〜30 サイクル）に、音データの読み込み（ADPCM の展開）を足す。**未実装・ADPCM の展開の速さは未測定**。

### 2-5. ピアノとドラムを同時に鳴らす（Mac につないでいるとき）と、「駒がないときも鳴る」ドラム

**なぜ、いまは低い音になるのか**: GarageBand は、選んでいる1つのトラックに、全チャンネルの MIDI をまとめて入れます。ドラムはチャンネル10 で送っていますが、そのトラックの音源（ピアノ）には、「チャンネル10 はドラム」という考えがなく、ノート36（キック）・42（ハイハット）を、低い C と F# のピアノの音として鳴らします。

**方法**（上から順に、手軽な順）:

| # | 方法 | 確かさ | ターミナル |
|---|---|---|---|
| 1 | **GarageBand のトラックの音源を、Apple の GM 音源（`DLSMusicDevice` か `AUMIDISynth`）に替える** | **成功（ユーザーが確認、2026-10-19）**。部品は **[実測]**（この Mac に入っていて、`auval` の検証に合格）。手順は README 6-5 | ブリッジだけ（`sh tools/run.sh`） |

3. 「空のプロジェクト」→「ソフトウェア音源」→「作成」。
4. 画面の「Smart Controls」ボタン（または B キー）→「プラグイン」→「インストゥルメント」の右側をクリック →「AU Instruments」→「Apple」→ **AUMIDISynth**（なければ DLSMusicDevice）。

**結果: 成功しました（ユーザーが確認）。** 手順は README 6-5 に書きました。

**「駒がないと無音」について**: ファームを調べて、パソコン上のテストを足しました（`test_groove.cpp` の 20）。
- **ドラムは、駒と無関係に、毎マス鳴ります。** 全部の位置が空でも、START すれば、ドラムだけが流れます。駒を置くと、次のステップからピアノが加わります。**[実測: パソコン上のテスト。実機では未確認]**
- いま無音になるのは、**起動時の標準が「ドラムなし」**だからです（`STATUS` に「ドラム: なし」）。
- 製品の動きとして、こう変えました（**実装・実機確認済み**、ユーザーの承認あり、2026-10-19）:
  1. 電源を入れたら、自動で再生を始める（START を打たない）。`AUTOSTART OFF` で、これまでの動きに戻せる。

  3. 止める・始めるのボタンは、スイッチを付けるとき（5章）に実装する。

  - 駒を登録するときは、先に `STOP`（再生中は、置いた駒は再生に使われる）。

## 5. ピンの予算（8台のリーダー + LED 18〜20 + エンコーダー 2〜3 + スイッチ 7〜8 + 音）

**結論: 1枚の ESP32-S3 に、そのままつなぐと、足りません。** 工夫して1枚に収めることも、2枚に分けることもできます。

### 5-1. 使えるピンの数

ふつうに使えるのは **25 本**です（私の数え方 **[調査]**）: GPIO 1, 2, 4〜18, 21, 38〜42, 47, 48。
使えない、または避けるピン: 0・3・45・46（起動時の設定に使われる）、19・20（USB）、43・44（シリアル）、26〜37（フラッシュと PSRAM）。
いま使っているのは 20 本（リーダー 16 + 共有 SPI 3 + ブザー 1）。**空きは 5 本**（GPIO 2、38・39・40、48）。**この基板に SD スロットはなく、38〜40 は完全に空き**です（写真で確認 **[実物確認]**。以前の「SD 兼用」は誤りでした）。GPIO2 には基板上の LED（IO2）、48 には RGB LED が付いています（使うと光ります。使うこと自体はできます）。

### 5-2. 必要な本数

| 部品 | 数 | そのままつなぐと | 工夫すると |
|---|---|---|---|
| RC522 リーダー | 8 | 19（共有 3 + SDA 8 + RST 8） | 11（**RST を 3.3V につなぐ**と −8） |
| LED | 18〜20 | 18〜20 | **1**（数珠つなぎにできる LED = WS2812 / SK6812 系なら、データ線 1 本） |
| ロータリーエンコーダー | 2〜3 | 4〜6（押しボタン付きなら +2〜3） | 2〜3（**I2C の拡張 IC**で、スイッチと共用） |
| タクトスイッチ | 7〜8 | 7〜8 | 〃 |
| 音（I2S アンプ） | 1 | 3 | 3 |
| ブザー | 1 | 1 | 0（音が出せれば不要） |
| **合計** | | **約 38〜41**（LED を数珠つなぎにしても） | **約 17〜19** |
| 使える数 | | **25** | **25** |

- LED を 1 個ずつ別のピンにつなぐなら 57 本以上で、論外です。**数珠つなぎ型の LED**（1個ずつ色と明るさを変えられる）にしてください。1 色の LED を使うなら、シフトレジスタ（74HC595 を 3 個、ピン 3 本）などが必要です（明るさの調整は難しくなります）。
- 「RST を 3.3V につなぐ」: 今の標準の止め方（RESET）は使えなくなり、「アンテナOFF」になります。**8台・8枚の測定で、2つの止め方に差はありませんでした**（読めた率 100%、干渉 0）**[実測]**。ただし、配線を変えたら、もう一度測る必要があります。
- さらに削る必要が出たら、SDA（チップセレクト）を、74HC138（3→8 デコーダー）で 8 本から 4 本にできます（ライブラリの呼び方の工夫が要ります）。

### 5-3. 収め方は3通り

| | やり方 | ピン | 配線のやり直し | 向いている場面 |
|---|---|---|---|---|
| **A. 1枚に収める** | RST を 3.3V に / LED は数珠つなぎ / スイッチ類は I2C 拡張 IC | 約 17〜19 / 25 | **要**（リーダーの RST の線 8 本を外す） | 最終版（専用基板）の形 |
| **B. 2枚に分ける（おすすめ）** | **もう1枚の ESP32-S3 を、「Mac の代わり」にする**。今の1枚目は、そのまま（駒の読み取り + 進行）。2枚目が、音（I2S）・Wi-Fi の操作画面・LED・エンコーダー・スイッチを担当 | 1枚目: 22 / 25、2枚目: 20〜23 / 25 | **不要** | **プロトタイプ** |
| C. 1枚目に全部 + 空きピンぎりぎり | I2S 3 + LED 1 + I2C 2 = 6 本。ブザーを外して空きが 6 本 | 25 / 25（余裕なし） | 不要 | 非推奨（表示器などを足せない） |

**B をおすすめする理由**:
1. **今の配線を触らなくてよい**（動いている8台を壊さない）。
2. **いまの構成と同じ形**: 「ESP32 ←→ Mac（ブリッジ + 音源 + 操作画面）」の Mac を、2枚目に置き換えるだけ。今の文字のやりとり（コマンド、`~M` の MIDI、`~S` の状態）を、そのまま使えます。1枚目のソフトは、ほとんど変わりません。
3. **時間に厳しい処理を分けられる**: 駒の読み取りは、200ms ごとに止まって待つ処理です。音の計算・Wi-Fi・LED の更新・スイッチの反応と同じ ESP32 に同居させると、互いに邪魔するおそれがあります（測定では、音と読み取りの同居は問題なかったが、Wi-Fi と LED は未測定）。
4. 2枚目のピンに余裕がある（LED・スイッチを足しても足りる）。

**2枚構成と、拡張IC（1枚に収める）の比べ方**（2026-10-19 のご質問への答え。数字は目安で、**応答時間は私の見積もり [未測定]**）:

| | **B. 2枚目の ESP32-S3** | **A. 拡張 IC（MCP23017 など）+ RST を 3.3V に** |
|---|---|---|
| 追加の部品代 | 0円（お持ちの1枚） | 数百円 × 1〜2個（スイッチ・エンコーダー用） |
| 追加の面積 | 開発ボード1枚ぶん（LED・スイッチ・アンプと同じ板の上に置ける） | IC 1個ぶん（DIP-28 で 約 3.6cm × 1cm）。ほぼゼロ |
| 配線の手間 | 1枚目↔2枚目: **3本**（TX・RX・GND）+ 5V の共有。**今の配線は触らない** | 拡張 IC ↔ ESP32: 4〜5本（SDA・SCL・3.3V・GND・割り込み）+ **リーダー8台の RST の線を外して 3.3V につなぐ（8本の付け替え）** |
| ソフトの手間 | 2枚目に、音・画面・LED・スイッチを**新しく**作る（どちらの案でも必要な機能）。1枚目は、通信（UART）を足すだけ | 同じ機能を、1枚の中に作る。リーダーの RST を使わない形に**書き換え**（動いているコードを触る） |
| スイッチを押してから反応するまで | 約 1〜30ms（2枚目が押下を直接見て、UART で 1枚目に伝える。1枚目は読み取りの合間に受け取る） | 約 5〜30ms（読み取りの1周ごとに拡張 IC を読む。専用のタスクで読めば短くできる） |
| エンコーダー（回転）の取りこぼし | 起きにくい（2枚目が専用で見張る） | 読み取りの処理と同居するので、**速く回すと取りこぼす可能性**（割り込みか専用タスクで対策が要る） |
| 音・Wi-Fi・LED と、駒の読み取りの干渉 | 別のチップなので、**互いに邪魔しない** | 同じチップ。音と読み取りの同居は測定済みで問題なし。Wi-Fi・LED との同居は**未測定** |
| 壊れたとき | 1枚ずつ切り分けられる | 1枚の中で切り分ける |
| 製品にしたとき | 2枚の ESP32 を載せる（コスト増）か、専用基板で1枚にまとめる | **最終版の形**（専用基板に ESP32-S3 のモジュール + 拡張 IC） |

**結論**: プロトタイプは **B**（手間が少なく、今の配線を壊さない。部品代 0円）、最終版は **A の形**（専用基板）。B で作ったソフト（音・画面・LED・スイッチ）は、A にそのまま移せます。**B の追加の手間は、3本の線と、1枚目の UART の追加だけ**です。

**B の注意**: 2枚の間は、UART（TX と RX を交差、GND を共通）。**1枚目の USB 側のシリアル（43・44）には、つながないでください**（パソコンとの通信とぶつかります）。1枚目の空きピン（38・39 など）に、UART1 を割り当てます。ファームの変更が要ります。

**将来の最終版**は A（専用基板に ESP32-S3 のモジュールを載せる）が自然です。B で作った機能は、そのまま A に移せます。

### 5-4. LED の注意（数珠つなぎ型を使うとき）

**「数珠つなぎ型」= テープライトのことではありません。** WS2812 という LED は、内蔵の小さな制御 IC で、1個ずつ色と明るさを変えられます。信号の出入り口（DIN と DOUT）があり、**1個目の DOUT を、2個目の DIN につなぐ**ように、順番にたどってつなぐと、ESP32 の信号線1本で全部を制御できます。テープライトは、これを細長い帯に並べたものです。
**お考えの「1個ずつ独立した WS2812 のブレークアウトモジュール」を、自由な場所に離して置く使い方で、まったく問題ありません**（同じ仕組みです）。

- 配線: モジュール同士は、**3本（5V・GND・信号 DOUT→DIN）**でつなぎます。20個なら、約60本。5V と GND は、太い線で共通のバスにまとめて、そこから各モジュールに分けると、信号線は1本ずつの鎖で済みます。
- **順番は自由**です。「何番目の LED が、どの位置か」は、ソフトの表で対応づけます（置く場所を変えても、表を書き換えるだけ）。
- **鎖のどこかが切れる（線が外れる）と、そこから先の LED は全部消えます**。コネクタかはんだで、しっかり接続してください。
- 1区間の線は、数十cm 以内が無難です（各 LED が信号を整えて次に渡すので、全体が長くなること自体は問題ありません）。

- 1 個あたり最大 約 60mA（全部白で最大輝度のとき）。**20 個で最大 約 1.2A**。明るさを 20〜30% にすれば、約 0.3A。**パソコンの USB（0.5〜0.9A）では足りません。5V 2A 以上の電源を用意してください**（アンプも電流を使います）。
- データ線は 3.3V の信号で、LED は 5V で動きます。**信号が足りなくて、不安定になることがあります**。バッファ IC（74AHCT125 など）を 1 個はさむのが確実です。
- 電源の線は太く短く、LED の電源の近くにコンデンサ（数百 µF）を。
- LED のデータ線は、リーダーのアンテナから離してください（読み取りへのノイズを避けるため）。
- ESP32-S3 は、LED の信号を、専用の回路（RMT）で出せるので、CPU は止まりません。**[調査]**

### 5-5. 配線を変えるときの危険

**RST の線を 3.3V につなぐなら、ファームで、その GPIO を「出力にしない」ように、同時に変える必要があります。** 出力のまま LOW にすると、3.3V と GND が GPIO でショートして、ピンを壊します。配線を変える前に、必ずご相談ください（ファームを先に直します）。

- GarageBand のトラックの音源を Apple の GM 音源に替える方法（2-5 の方法1）: **成功**。
- 2枚目の ESP32-S3: **いまの1枚目と全く同じ基板**。
- 2枚構成: 「スペース・応答時間・手間が大きくなりすぎなければ可」→ 5-3 の比較表のとおり、**手間は 3本の線と UART の追加だけ**。
- LED: **1個ずつ独立した WS2812 のブレークアウトモジュール**を想定 → 5-4 のとおり、そのままでよい。
- 起動したら自動で再生・標準ドラム 8ビート: **承認 → 実装・実機確認済み**。

**まだの確認**
1. ~~M0（USB-MIDI の直結テスト）~~ → **やらない**（2026-10-19）。GarageBand が Apple の GM 音源で鳴るようになり（README 6-5）、**ケーブル1本（UART 側）**で足りるため。USB-MIDI は未確認のまま残す。
2. **試聴ファイルの音質は、許容範囲か**（グランドピアノ / エレピ）。
3. **部品を買ってよいか**: I2S アンプ（MAX98357A）+ スピーカー。保険の Unit Synth も買うか。
4. **操作は、スマホ・タブレットでよいか**。つまみ・ボタンは、先に作る LED・スイッチ・エンコーダーで足りるか。
5. **将来、売ることを考えているか**（音源の権利、駒の方式に影響します）。

## 10. 方向性についての私の意見: 「単体で完結」か「Mac につなぐ前提」か（2026-10-19）

**結論: 今は決めなくてよい。「MIDI を出す本体」を軸にして、どちらにも進める形で、共通の機能から進めるのがよい。**

| | A. 単体で完結 | B. Mac につなぐ前提 | C. 二段構え（私のおすすめ） |
|---|---|---|---|
| 製品体験 | ◎ 電源を入れるだけ | △ Mac と GarageBand の準備が要る | ◎ 単体でも鳴る。つなげば、さらに良い音 |
| 音質 | 内蔵音源の出来しだい（SD を使えば高い） | ◎ GarageBand の本物の音源 | 単体は「十分よい」、Mac は「最高」 |
| 開発量 | 大（音源・スピーカー・Wi-Fi 画面・登録） | 小（ほぼ済） | 大（A とほぼ同じ） |
| 部品・費用 | アンプ・スピーカー（・SD） | なし | A と同じ |
| 誰に向くか | 人に渡す・売る | 自分で使う・開発 | 両方 |

私の考え:
1. **この玩具の価値は、「駒を置く → コード進行 → MIDI」の部分**で、ここは完成しています。音は MIDI の先にあるので、**あとから差し替えられます**（Mac でも、内蔵音源でも、音源モジュールでも）。だから、**音源の最終形を急いで決める必要はありません**。
2. **決める軸は3つ**です。(a) 誰が使うか（自分だけ／人に渡す・売る）、(b) 音質をどこまで優先するか、(c) 1年後にどうなっていたいか。「人に渡す・売る」なら A か C、「自分の楽器として深く使う」なら B で十分です。
3. **SD カードの件は保留でよい**です。SD で得られるのは「ピアノの音の上質化」だけで、LED・スイッチ・Wi-Fi の画面・登録の画面などの**ほかの機能とは独立**だからです。
4. **どちらの方向でも必要で、いま進めてよい機能**:
   - 駒の置き換えの即時反映（済）、自動再生・設定の保存（済）、常駐ブリッジ（済）。
   - **LED**（位置・いまのステップの表示）、**スイッチ・エンコーダー**（START/STOP・BPM・キー・パターン）。
   - **2枚目の ESP32 との UART 通信**（5-3 の B）。2枚目を「Mac の代わり」にする構成は、**A でも C でも使えます**。
   - **Wi-Fi の操作画面**（ESP32 自身が配る）。Mac があってもなくても、スマホで操作できます。
   - **駒の登録を画面から**（Mac なしで登録できる）。
5. 音のほうは、**音色の方向性を聞き比べで絞る**ところまでにしておきます（いまここ）。方向（ピアノ中心か、エレピ・パッドも欲しいか）が決まれば、必要な音源データの大きさが分かり、内蔵（フラッシュ 16MB）で足りるか、SD が要るかが決まります。

## 11. 優先順位の決め方: 「こう進めたいなら、これを優先」（2026-10-19）

「何を先にやるか」は、好みではなく、**物差し（指標）**で決められます。まず物差しを示し、次に「進めたい方向」ごとの早見表を示します。

### 11-1. 5つの指標

| # | 指標 | 問い | 高いとき |
|---|---|---|---|
| 1 | **ブロッカー度** | これが終わらないと、ほかの作業・実験が進められないか | **先に** |
| 2 | **後戻りの高さ** | 後から変えると、配線・筐体・ピン配置の作り直しになるか | **早めに「決める」**（作り込むのではなく、方針を決める） |
| 3 | **不確実さ** | 実際に測るまで、できるかどうか分からないか | **早く、小さく試す**（当たり外れを早く知る） |
| 4 | **待ち時間** | 部品の取り寄せ・筐体の製作・人への依頼など、待つ時間があるか | **今のうちに発注・依頼**（待つ間に、ほかをやる） |
| 5 | **目的への効き** | 評価実験（12月）や展示（2〜3月）に、直接効くか | 低ければ**後回し** |

**使い方**: 1〜4 のどれかが高い作業は先に。5 が低く、あとから差し替えられるもの（音色の好み、画面の見た目の磨き）は後に。
迷ったら、「**これをやらないと、次の実験ができなくなるのは、どれか**」を選ぶ。

### 11-2. 進めたい方向ごとの早見表

| こう進めたい | 先にやること（理由の指標） | 後回しでよいこと |
|---|---|---|
| **A. 12月の評価実験を、確実にやりたい**（初心者と経験者で比べる） | ① **駒の読み取りの確実さ**（誤読・読み落としがあると、実験の結果が信用できない → #1）。**影の対策は済**（README 4-5）。② **コードの「働き」（トニック・サブドミナント・ドミナント）のデータと、見せる手段**（LED の色・画面）。ポスターの独自性なのに、ファームにまだデータがない → #1 #5。③ **実験の記録**（どの駒を、いつ、どの順で置いたか。ログ出力）→ #1。④ 電源を入れるだけで動く（済） | SD、音の最高品質、細かい操作 |

### 11-3. あなたの状況に当てはめた、私の推奨順（根拠つき。方向が決まれば変わります）

ポスターの予定は、10月＝試作1（駒の認識 + LED + 音 + 筐体）、11月＝試作2（鍵盤の連携・操作・外観）、12月＝評価実験、1月＝改善、2月＝最終モデル、3月＝展示でした。これに合わせると:

1. **駒の読み取りの確実さ**（影の対策は完了。リーダーの間隔は、筐体の設計に先に反映する）— #1 #2
2. **コードの「働き」のデータ**（トニック・サブドミナント・ドミナント、裏コードのつながり）— ポスターが「独自性」としているのに、ファームに無い。#1 #5
3. **LED**（位置・いまのステップ・働きの色）— 少ない手間で、体験への効きが大きい。ピン1本。#5

5. スイッチ・エンコーダー・LCD・鍵盤 — 11月の試作2に合わせて。
6. SD・音源の最高品質 — 方向（ピアノ中心か）が決まってから。後から足せる。
