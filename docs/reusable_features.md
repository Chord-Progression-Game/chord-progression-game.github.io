# 引き継ぎ資料 — 実装済みの機能と、新しい作品への持ち込み方

作成: 2026-11-08 ／ 対象: `ESP32_Octo_01`（RC522 8台版）の、2026-10-19〜20 時点の状態

新しい方向性の作品を作るときに、**今あるものから何を踏襲できるか**を、機能ごとにまとめました。
各項目に、「どこにあるか」「何をするか」「確かさ」「持ち込みやすさ」を付けています。

| 持ち込みやすさ | 意味 |
|---|---|
| ◎ | そのまま使える（作品の内容に依存しない） |
| ○ | 少し直せば使える（コードの種類など、この作品の決めごとが一部入っている） |
| △ | 考え方・構成は使えるが、作り直しに近い |
| ✕ | この作品（コード進行のおもちゃ）専用 |

| 確かさ | 意味 |
|---|---|
| **実機** | 本物のボード・本物の駒で確認した |
| **PCテスト** | パソコン上の自動テストで確認した（実機では未確認の部分がある） |
| **測定のみ** | 測っただけで、製品には組み込んでいない |
| **未確認** | まだ確かめていない |

## 2. 全体の層構造（どの層が、どの作品でも使えるか）

```
[駒の認識]  RC522 ×8 ─ reader_array ─ array_tracker ─ board / layout ─ tag_store
                 （◎ 作品に依存しない）                 （◎）           （○ 駒の意味はIDで持つ）
                                   ↓ 「位置 n に 駒 ID が置かれた」
[意味づけ]  chords → voicing → groove ← rhythm（パターン）          ★ここが作品ごとに変わる層
                 （✕/○ コード専用）        （◎ 時間の管理 + パターン再生）
                                   ↓ MIDI の指示（音の高さ・強さ・長さ）
[出力]      player → midi_out → なし / ブリッジ（UART）/ USB-MIDI     （◎）
                                   ↓
[PC側]      midi_bridge.py → 仮想MIDI → GarageBand（AUMIDISynth）/ gm_synth   （◎）
            rhythm_server.py + 操作画面（ブラウザ）                          （○）
[保存]      NVS: chordtag（駒）/ rhythm（自作パターン）/ settings（設定）    （◎）
[道具]      テスト・診断・書き込み・常駐                                    （◎）
```

**いちばん大事な点**: 「駒を置く → どの位置に何があるか分かる」の層（上）と、「MIDI を出す」の層（下）は、**作品の内容に依存しません**。コード進行という意味づけは、真ん中の層だけです。新しい作品でも、上と下をそのまま使い、真ん中だけを差し替えられます。

## 4. 実測・調査で分かったこと（新しい作品でも役に立つ）

**ハードウェア**
- Freenove ESP32-S3 WROOM（FNK0085）は、**フラッシュが実物 16MB**（PlatformIO の設定は 8MB）。**microSD スロットは付いていません**（ユーザーの写真で確認。以前の私の説明は誤りで、訂正済み）。
- 使えるピンは約25本。**避けるピン**: 0・3・45・46（起動時の設定）、19・20（USB）、43・44（シリアル）、26〜37（フラッシュ・PSRAM）。**GPIO15・16 は、ふつうの GPIO として使えた**（32kHz の水晶用のピンでもあるが、問題なし）。
- RC522 を8台、同じ SPI につなぐと、**MISO を離さない問題**がある。RST を台ごとに分けて、使っていない台を止めると安定。
- RC522 を約6cm 間隔で並べると、**隣のリーダーが駒を読む「影」**が出る。推奨は 8〜10cm 以上。ファームの対策で、間隔が近くても動く（同点のときは見分けられない）。
- ESP32-S3 は、**倍精度（double）の計算が遅い**。音の計算では、整数か float にする。
- 読み取り: 待ち 8ms・返事 10ms が安定（5ms では、4台回しで60回に1〜2回の読み損ない）。

**ソフト・開発の落とし穴**
- Python からシリアルポートを開くと、**ボードが再起動する**。いまは自動再生が始まるので、登録の画面のコマンドを使う前に `STOP` を送る。リーダーに駒があるときは、登録の確認 `y/n` に **必ず `n`** で答える。
- `pio run` を `head` や `grep -m` にパイプしない（SIGPIPE でビルドが壊れる）。ファイルに出してから grep。
- pyserial の `read(512)` は、512バイト溜まるまで待つ（MIDI が最大50ms遅れる）。`read(1)` + `read(in_waiting)` にする。
- 作業中、**ファイルが古い内容に2回、勝手に戻ったことがある**（原因は不明）。重要な変更のあとは、`grep` とテストで確認する。**このフォルダは git で管理されていません**。新しい作品では、最初に `git init` を推奨します。
- `run_all.sh` は、以前、コンパイルに失敗しても「すべて合格」と出す不具合があった（修正済み）。

## 5. 新しい作品に持ち込む手順（提案）

1. **新しいフォルダに複製する**: `rsync -a --exclude '.pio' --exclude 'tools/.venv' --exclude '__pycache__' ESP32_Octo_01/ 新しい名前/`（今回の複製と同じ方法）。`sh tools/setup_bridge.sh` で Python の環境を作り直し、`sh tools/host_tests/run_all.sh` で、複製が壊れていないことを確認する。**複製したら、すぐ `git init`**。
2. **層ごとに、残すものと捨てるものを決める**:
   - 残す（◎）: `reader_array` / `array_tracker` / `layout` / `board` / `tag_store` / `midi_out` / `midi_protocol` / `settings_store` / `cmd_parse` / `rc522_test` / ブリッジ / 常駐 / テスト一式。
   - 作り替える（✕・△）: `chords` / `voicing` / `register_ui` の文言 / 操作画面の中身。
   - 流用する（○）: `groove` / `rhythm`（「ステップ」と「パターン」を、新しい作品の言葉に置き換える）。
3. **NVS の `chordtag`（18個の駒）は、消さない**。新しい作品が別の意味づけをするなら、**別の名前空間**（例: `tagnew`）を使い、`tagStoreBegin("名前")` に渡す。元の駒の登録を壊さない。
4. **ボードを共有するときの注意**: 常駐ブリッジがポートを持っているので、書き込み前に `chordtoy_agent.sh stop`（または `upload.sh`）。新しい作品用のブリッジの名前（`jp.chordtoy.bridge`、仮想ポート名）が、古いものとぶつからないようにする。
5. **配線を変えるとき**: ピン表（`reader_array.cpp`）と `config.h` が、「正」。ピンを足す前に、README 3章と `standalone_plan.md` 5章の予算を見る。**RST を 3.3V につなぐ場合は、ファームでその GPIO を出力にしない**（ショートの危険）。

## 6. まだ未完・未確認のこと

- **ポスターの独自性**（コードの働き：トニック・サブドミナント・ドミナント、裏コード、LED の光の演出）は、データも判定も**未実装**。
- **LED・ツマミ・スイッチ・液晶・25鍵キーボード**: 未実装。LED は WS2812 の個別モジュール（1本のデータ線で数珠つなぎ）の方針。25鍵の扱い（市販か自作か）は未決定。
- **単体で音を出す**: アンプ・スピーカー未購入、組み込み未着手。「Mac につなぐ前提」か「単体で完結」かを、ユーザーが決めていない（`standalone_plan.md` 10・11章）。2枚目の ESP32-S3（同じ Freenove）は手元にある。
- **影の仕組みは未解明**。ブレッドボードに刺さっているので、間隔・電源の実験ができていない。
- `MAP LEARN`（実際の並びの登録）、再生中の駒の交換（実機）、USB-MIDI、3.3V の実測、アンプが RC522 に与える影響: **未確認**。
- 駒や筐体のデザインは、私の作業範囲外で、進み具合は把握していない。
